# 公众号图文排版

用用户的文章、图片和偏好生成可在浏览器预览、复制正文的独立 HTML。网页不调用 AI；AI 负责整理内容、调整规则和重新生成。

## 输入与交付

- 先确认当前任务指定的文章和图片。不要从其他项目、历史会话、账号目录中搜集业务内容来填充。
- 用户没有指定样式时，以示例的简洁版式作为起点；示例诗文和绘画不是每篇文章的固定内容。
- 把输入整理为 `article.json`，把字号、颜色、间距等保存到独立 `layout.json`。格式见 [输入说明](assets/input-format.md)。
- 用 `python3 scripts/build_article.py ARTICLE_JSON --layout LAYOUT_JSON --output OUTPUT_HTML` 生成。路径按当前 Skill 目录解析。脚本只有 Python 标准库依赖，不请求网络。
- 交付 HTML、输入文件、图片和配置。新稿默认另存，修改原稿时遵循用户指定范围。

## 排版与复制

- 在文章节点内保留内联样式；单纯依赖网页外层 CSS 的格式不一定随复制保留。
- 图片使用内嵌 data URL，输出不要依赖本地绝对路径、临时 blob URL、远程图床或外部字体。
- 图片保持原比例；顺序和并排关系以用户材料为准。脚本支持单图、双图及上下排列。
- 保留按钮点击触发的 `text/html` 与 `text/plain` 复制、图片加载检查、体积检查和失败提示。
- 10 MB 是本工具的保护阈值，不是已确认的微信限制。超出时先压缩图片或分篇，不虚报复制成功。
- 并排布局可能在公众号被改为上下排列；图片也可能无法被接收。网页显示正常或剪贴板写入成功都不能证明公众号粘贴成功。不要为了并排而默认把两张图片拼成一张；应先说明这会改变编辑方式。

## 迭代与验证

- 从用户反馈中提取具体改动，如字号、两图顺序、留白、手机宽度；改配置后重新生成，不随意重写原文。
- 检查图片数量、缺图、文本转义、桌面与窄屏预览，最后由有权限的一方在公众号空白正文粘贴检查。
- 无法访问公众号时明确只验证了本地预览与复制，不模拟成已验证的后台结果。
- 满意后保留 `layout.json`；脚本未覆盖的新样式可在独立 HTML 或模板副本中实现，并写入该用户的排版说明。
- 网页只复制正文。文章标题、摘要、封面需在公众号单独填写和上传。不自动保存草稿或发布。
- 没有文件处理能力的聊天工具可协助整理需求，但不能保证它能生成可下载文件。可让用户在本地运行脚本，或交付待运行文件。
